Configuration reference

Every setting of every IsleDB service. Guidance on choosing values is on each service's page: writer, reader, maintenance and read cache.

How settings work

Each setting can come from a YAML file, an environment variable or a flag. A flag overrides the environment, the environment overrides the file, and the file overrides the default.

isledb writer --config /etc/isledb/isledb.yaml
  • One file for every service. Settings shared by all services sit at the top; each service reads its own section (writer:, reader:, maintenance:, cache:) and leaves the others alone.
  • Unknown keys are errors, at the top and inside a service's section, so a misspelled setting stops the service at start instead of being ignored.
  • Environment variables are ISLEDB_ followed by the key, upper case, with dots as underscores: writer.flush.interval is ISLEDB_WRITER_FLUSH_INTERVAL, and bucket_url is ISLEDB_BUCKET_URL. A variable set to an empty value counts as set.
  • Sizes take binary units: 512KiB, 256MiB, 8GiB, 2TiB. Durations look like 250ms, 30s or 2m.
  • --check prints every setting with its final value, or the problems it found, and exits without starting the service.
  • No secrets in the configuration. It names files that hold tokens and keys; storage credentials come from the provider's usual places.

Authentication, TLS and shutdown

The writer, reader and read cache share these settings, each under its own section. Replace <service> with writer, reader or cache, and <SERVICE> with WRITER, READER or CACHE.

Setting Default Description
<service>.auth.token_file
--auth-token-file
ISLEDB_<SERVICE>_AUTH_TOKEN_FILE		 File of accepted tokens, one per line. Reread on SIGHUP.
<service>.auth.insecure
--insecure
ISLEDB_<SERVICE>_AUTH_INSECURE		 false Accept requests without a token. For development only.
<service>.tls.cert, <service>.tls.key
--tls-cert, --tls-key
ISLEDB_<SERVICE>_TLS_CERT, ISLEDB_<SERVICE>_TLS_KEY		 Serve HTTPS with this certificate and key.
<service>.tls.client_ca
--tls-client-ca
ISLEDB_<SERVICE>_TLS_CLIENT_CA		 Require clients to present a certificate signed by this CA.
<service>.shutdown_drain
--shutdown-drain
ISLEDB_<SERVICE>_SHUTDOWN_DRAIN		 5s How long the service reports not ready before it shuts down, so load balancers stop sending it traffic.

A service with an API refuses to start without a token file or a client CA, unless auth.insecure is set. See Secure IsleDB.

Writer

Setting Default Description
writer.prefix
--prefix
ISLEDB_WRITER_PREFIX		 required The database's path in the bucket; / for the root of the bucket.
writer.owner_id
--owner-id
ISLEDB_WRITER_OWNER_ID		 host name A name for this writer, shown in logs and storage. In Kubernetes, use the pod name.
writer.flush.interval
--flush-interval
ISLEDB_WRITER_FLUSH_INTERVAL		 250ms; 1s on gs:// How often writes are saved. At least 1s on Google Cloud Storage. See Choose the flush interval.
writer.writes.commit_wait
--commit-wait
ISLEDB_WRITER_WRITES_COMMIT_WAIT		 10s How long a write waits to be saved before the client gets 504. Longer than flush.interval, and at most 20s.
writer.values.max_key_bytes
--max-key-bytes
ISLEDB_WRITER_VALUES_MAX_KEY_BYTES		 65527 Largest key accepted, in bytes. At most 65527.
writer.values.max_value_bytes
--max-value-bytes
ISLEDB_WRITER_VALUES_MAX_VALUE_BYTES		 16MiB Largest value accepted.
writer.writes.max_request_bytes
--max-request-bytes
ISLEDB_WRITER_WRITES_MAX_REQUEST_BYTES		 32MiB Largest batch request. At least 1MiB.
writer.memtable.target_bytes
--memtable-bytes
ISLEDB_WRITER_MEMTABLE_TARGET_BYTES		 16MiB How much data the writer buffers before saving it in a separate group. Also the largest batch.
writer.memtable.max_pending
--max-pending-memtables
ISLEDB_WRITER_MEMTABLE_MAX_PENDING		 4 How many full groups can wait to be saved before new writes get 503.
writer.l0_merge.target_bytes
--l0-merge-bytes
ISLEDB_WRITER_L0_MERGE_TARGET_BYTES		 64MiB The writer keeps the files it recently saved in memory and combines them into one larger file once they hold this much. Uses up to about three times this much memory: twice this in saved files, and the combined file while it uploads. Smaller makes fewer recent files for a scan to read; larger means less rewriting. See Memory.
writer.l0_merge.max_age
--l0-merge-max-age
ISLEDB_WRITER_L0_MERGE_MAX_AGE		 5m How long a saved file is kept in memory before what is kept is combined, whatever its size.
writer.writes.max_inflight_bytes
--max-inflight-bytes
ISLEDB_WRITER_WRITES_MAX_INFLIGHT_BYTES		 256MiB Memory for requests being read and applied at once. A PUT counts its body; a batch counts 4 times its body. Past it, new writes get 503 until earlier ones finish. At least 4 × max_request_bytes, and max_value_bytes.
writer.writes.body_read_timeout
--body-read-timeout
ISLEDB_WRITER_WRITES_BODY_READ_TIMEOUT		 1m How long a client has to send its request body. Past it, the client gets 408.
writer.change_feed.payload
--change-feed
ISLEDB_WRITER_CHANGE_FEED_PAYLOAD		 empty Turns on the database's change feed: keys or values. Empty keeps what the database has. Once on, it stays on, and its mode can't change.
writer.policy.max_pinned_view_age
--max-pinned-view-age
ISLEDB_WRITER_POLICY_MAX_PINNED_VIEW_AGE		 1h Must match the database's setting. Leave it unset unless the database was created with a different value; otherwise the writer won't start.
writer.listen
--listen
ISLEDB_WRITER_LISTEN		 :8070 Address for the API.
writer.admin_listen
--admin-listen
ISLEDB_WRITER_ADMIN_LISTEN		 127.0.0.1:8071 Address for health checks and metrics. Empty turns it off.

Maintenance

Setting Default Description
maintenance.prefix
--prefix
ISLEDB_MAINTENANCE_PREFIX		 required The database to maintain; / for the root of the bucket.
maintenance.scratch_dir
--scratch-dir
ISLEDB_MAINTENANCE_SCRATCH_DIR		 the user's cache directory Where compaction keeps the files it is merging. Use a local disk.
maintenance.change_feed.retain_for
--change-feed-retain-for
ISLEDB_MAINTENANCE_CHANGE_FEED_RETAIN_FOR		 0s How long change-feed history is kept; 0s keeps it all.
maintenance.compaction.base_level_bytes
--base-level-bytes
ISLEDB_MAINTENANCE_COMPACTION_BASE_LEVEL_BYTES		 512MiB Target size of the first level below newly saved files. Each level after it is level_growth times larger. See Tune compaction.
maintenance.compaction.level_growth
--level-growth
ISLEDB_MAINTENANCE_COMPACTION_LEVEL_GROWTH		 8 How much larger each level is than the one above it. At least 2.
maintenance.compaction.target_sst_bytes
--target-sst-bytes
ISLEDB_MAINTENANCE_COMPACTION_TARGET_SST_BYTES		 64MiB Size of the files compaction writes.
maintenance.compaction.l0_to_base_ratio
--l0-to-base-ratio
ISLEDB_MAINTENANCE_COMPACTION_L0_TO_BASE_RATIO		 1 How much newly saved data collects, as a share of the first level, before it is merged into that level. Higher rewrites less, but leaves more files for a scan to read. Must be positive.
maintenance.compaction.l0_max_depth
--l0-max-depth
ISLEDB_MAINTENANCE_COMPACTION_L0_MAX_DEPTH		 16 Newly saved files a single key may be in before they are merged into the first level, whatever their size. Bounds the files a read checks.
maintenance.compaction.l0_max_age
--l0-max-age
ISLEDB_MAINTENANCE_COMPACTION_L0_MAX_AGE		 30m Age of the oldest newly saved data that makes it merge into the first level, whatever its size, so a database that stops being written settles.
maintenance.admin_listen
--admin-listen
ISLEDB_MAINTENANCE_ADMIN_LISTEN		 127.0.0.1:8061 Address for health checks and metrics. Empty turns it off.
maintenance.shutdown_drain
--shutdown-drain
ISLEDB_MAINTENANCE_SHUTDOWN_DRAIN		 0s How long to report not ready before stopping.

Maintenance serves no API, so listen, auth and tls don't apply to it: setting them is an error.
